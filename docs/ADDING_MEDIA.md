# Adding Media to EasyFlix

This is the canonical manual workflow for adding legally acquired local video files to an existing EasyFlix library without changing the EasyFlix application itself.

The key rule is simple:

> Media belongs in the user's media folders/drives. It does not belong in the EasyFlix source repository.

EasyFlix treats the existing filesystem as the source of truth. Adding a movie, TV show, or anime should therefore be a library-maintenance operation, not a software-development operation.

## Normal workflow

1. Put the new video file(s) under an already-configured EasyFlix library root.
2. Use a clean, descriptive folder/file name. Recommended conventions are below.
3. Open EasyFlix and run its normal local Refresh / library refresh operation.
4. Confirm that the new title appears in the correct category and that episodes are grouped correctly.
5. If you want provider artwork/description data, use the explicit metadata-sync action. Normal startup and Refresh should remain local-only.
6. Open the title and verify poster/title/year/category/episodes before considering the intake finished.

No source-code edit, database edit, rebuild, installer run, Git operation, Dev Relay mission, Codex session, or AI agent is required for normal media intake.

## Recommended naming

EasyFlix is intentionally tolerant of common release filenames, but predictable naming gives the scanner and metadata matcher the strongest possible signal.

### Movies

Preferred:

`Movies\Blade Runner 2049 (2017)\Blade Runner 2049 (2017).mkv`

Also acceptable:

`Movies\Blade.Runner.2049.2017.2160p.mkv`

When practical, keep the release-quality tokens in the filename but keep the containing folder human-readable.

### TV series

Preferred:

`TV Shows\The Leftovers\Season 01\The Leftovers - S01E01 - Pilot.mkv`

For later seasons:

`TV Shows\The Leftovers\Season 02\The Leftovers - S02E01.mkv`

### Anime series

Preferred:

`Anime\Samurai Champloo\Season 01\Samurai Champloo - S01E01.mkv`

Bare episode numbers inside a strong series folder can work, but `SxxEyy` is the safest cross-tool convention.

### Specials / OVAs / bonus episodes

Preferred when the episode can be represented conventionally:

`Anime\Series Name\Season 00\Series Name - S00E01 - OVA.mkv`

Low-information subfolders such as `Specials`, `Extras`, `Trailers`, and `Featurettes` should stay beneath the real movie/series folder so EasyFlix retains the parent title context.

## Adding a completely new folder or drive

If the files are already under a configured library root, nothing else is required.

If the files live outside all configured roots:

1. open EasyFlix library/settings management;
2. add the folder that should act as the new library root;
3. do not point EasyFlix at an entire drive when only one media subfolder is intended;
4. preserve any configured excluded/protected subfolders;
5. run Refresh;
6. confirm a few representative titles before adding a very large batch.

The filesystem remains authoritative. EasyFlix should not relocate or destructively reorganize the source media simply because a root was added.

The visual presentation is generated by EasyFlix, not by manually arranging files inside its source code.

A newly discovered title should automatically use the same:

- poster-card dimensions and `Stretch=Uniform` behavior;
- dark card/background treatment;
- movie / TV / anime grouping rules;
- focused details presentation;
- metadata confidence rules;
- local-first availability handling;
- playback/resume/history behavior;
- removable/offline handling;
- navigation and animation system.

You do not need to reproduce UI formatting when adding files. You only need to give the scanner a strong identity and then verify its result.

## If something is classified incorrectly

Do not immediately add a title-specific code hack.

Use this order:

1. inspect the file and parent-folder names;
2. rename only the new item to a clearer generic naming convention if that resolves ambiguity;
3. Refresh and check again;
4. if multiple ordinary files expose the same parser weakness, treat it as a generic EasyFlix parser/classification defect and fix the scanner with regression tests;
5. never hardcode one specific movie/show title merely to make the catalog look correct.

Examples of strong generic signals are year-qualified movie folders, explicit `SxxEyy` episode markers, meaningful series parent folders, and conventional Season folders.

## Safety rules

Normal intake must not:

- edit the EasyFlix SQLite database by hand;
- copy video files into the Git repository;
- alter protected/excluded folders;
- delete, move, or rename existing media in bulk;
- run provider/network synchronization silently at startup;
- overwrite existing subtitles/artwork without the normal EasyFlix safety rules;
- add title-specific production hacks.

If a drive is temporarily disconnected, EasyFlix should preserve historical catalog entries and mark availability appropriately rather than deleting the title from history.

## Dedicated EasyFlix handoff files

A completed text-format media handoff may use the dedicated .easyflixhandoff extension. Its contents use the same human-readable intake schema as the supported .txt handoff.

In Add Media Center, Enable .easyflixhandoff double-click registers a per-user Windows association for only that dedicated extension. Double-clicking such a file invokes the same native --import-handoff execution pipeline. The control can disable the association again.

EasyFlix never claims generic .txt files. Existing .txt and .json handoffs remain importable through Add Media Center, drag/drop, or the explicit --import-handoff CLI.

## Batch intake

For a large batch:

1. add a small representative sample first;
2. Refresh;
3. verify at least one movie, one episodic series, and one anime if those types are present;
4. then copy the remaining batch under the same naming structure;
5. Refresh again;
6. spot-check grouping and artwork.

This avoids turning a naming mistake into hundreds of badly classified entries.

## Quick reference

Existing root + well-named new file:

`copy file -> EasyFlix Refresh -> verify -> optional explicit Sync Metadata`

New root:

`add root -> Refresh -> verify representative items -> optional explicit Sync Metadata`

No software-development workflow should be needed unless a genuine generic scanner bug appears.
